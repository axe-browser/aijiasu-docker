# 爱加速 (Aijiasu) Linux Docker 独立代理服务 (Go 原生版本)

本项目是将**爱加速 (Aijiasu)** 官方 Linux 客户端容器化封装的高可用独立代理服务，宿主机管理端与多端口分发调度器采用 **Go 语言原生编译**，启动时间仅需数毫秒，无需任何 Node.js 运行时依赖。支持 ARM64 (Apple Silicon Mac) 与 AMD64 (x86_64 Linux/Windows) 双架构。

针对**指纹浏览器多环境独立专属配置**及**爱加速单账号并发连接数限制为 1** 的物理特性，本项目独创实现了**全量 2810 个节点独立专属端口智能分发引擎**：
**每一个爱加速可用节点，均分配一个专属独立的本地端口（共 2810 个端口，1080 ~ 3889）**。用户在指纹浏览器配置具体节点端口后，一旦发起访问，调度器自动秒级热切换至该节点并放行流量，完美实现“每个指纹环境锁定固定专属节点端口”的体验。

## 核心特性

1. **一节点一端口（全量 2810 端口覆盖）**：
   - 从 `1080` 开始，按全国省份与自然顺序连续分配 `1080 ~ 3889` 共 2810 个固定端口。
   - 每个端口严格对应一个具体的爱加速节点（包含专属节点 ID 与节点全称）。
   - **省份自然连续聚集**：同一个省份、城市的节点端口是高度连续整齐的（例如北京市 145 个节点端口为 `1080 ~ 1224`；上海市 146 个节点为 `1225 ~ 1370`；广州市 70 个节点为 `2295 ~ 2364`）。
2. **流量触发式按需秒级热切换**：
   - 指纹浏览器在任意环境发起请求时，调度器识别出目标节点，若当前底层连接不一致，在 **2~3 秒内自动完成加锁热切换**并无缝放行流量；后续同端口请求零延迟直通。
3. **单连接物理保护**：
   - 爱加速账号限制同时在线数为 1。分发器内部通过互斥排队锁进行切换管理，防止并发被服务端下发 `disconnected by another connection` 踢下线。
4. **SOCKS5 / HTTP 双模协议自适应**：
   - 2810 个端口全部支持纯透明 TCP 管道转发，客户端不论发起 SOCKS5 握手还是 HTTP CONNECT 隧道代理，均可原生兼容。
5. **双重全景视图**：
   - **平铺视图 (`aijiasu ports`)**：查看所有端口与节点的平铺对应表，支持按省份、城市、端口或名称快速筛选搜索（如 `aijiasu ports 北京`）。
   - **省份二级分类树状视图 (`aijiasu provinces` 或 `aijiasu ports -g`)**：严格遵循全国官方省份行政区划归类，树状展开各省份下辖城市与每个具体节点的专属端口。
6. **批量导出 CSV**：
   - 支持 `aijiasu ports --csv` 一键导出完整 CSV 表格，可直接批量导入 AdsPower、Hubstudio、比特浏览器、紫鸟等主流指纹浏览器。
7. **极速高并发架构**：
   - 纯 Go 原生实现，高并发激活全量 2810 个端口监听仅需 **67 毫秒**，常驻内存仅数十兆，单二进制文件仅 6.0MB。
8. **AES-256-GCM 硬件指纹强加密保管库 (杜绝明文泄露)**：
   - **启动智能预检**：执行 `aijiasu up` / `aijiasu start` / `aijiasu serve` 时，全自动检测本地凭据。若无凭据，触发安全交互录入（密码无回显）；若已有凭据，直接秒级无感解密拉起。
   - **杜绝明文存储**：彻底淘汰 `.env` 明文存储敏感账号密码的落后机制，采用主板硬件不可变 UUID 派生 256 位密钥加密托管至 `conf/.auth.enc` (POSIX 0600 私有权限)，拷贝到其他机器无法解密，杜绝代码泄露风险。
   - **凭据专属指令**：支持 `aijiasu auth` 查看加密状态、`aijiasu login` 更新账号密码、`aijiasu logout` 安全清除凭证。

## 协议支持与选型分析 (SOCKS5 vs HTTP)

爱加速 Linux 客户端在 `protocol proxy` 模式下**原生同时支持 SOCKS5 与 HTTP 代理协议**。针对指纹浏览器使用场景，两者对比分析如下：

### 1. 实测性能基准对比

| 测试指标 | SOCKS5 协议 (`socks5://`) | HTTP 代理 (`http://`) | 结论分析 |
| :--- | :--- | :--- | :--- |
| **本地代理建立耗时** | `0.0046 秒` (约 4.6ms) | `0.0024 秒` (约 2.4ms) | 本机 loopback 握手相差 2ms，人类完全无感 |
| **远端 TLS 握手耗时** | **`1.63 秒 ~ 2.85 秒`** | `5.47 秒 ~ 8.80 秒` | **SOCKS5 明显快 2~3 倍** |
| **整体网页请求总耗时** | **`3.25 秒 ~ 3.40 秒`** | `5.85 秒 ~ 8.89 秒` | **SOCKS5 整体效率更高** |

### 2. 底层机制与指纹浏览器业务场景对比

| 评估维度 | SOCKS5 协议（强烈推荐 🌟） | HTTP 代理 | 影响与安全考量 |
| :--- | :--- | :--- | :--- |
| **协议层级** | 4 层传输层（TCP 透明管道） | 7 层应用层（HTTP CONNECT 隧道） | SOCKS5 为纯二进制握手，无 Header 文本解析与内存拷贝开销 |
| **DNS 远程解析** | **100% 远端解析**（SOCKS5h 模式） | 多数远端解析，偶发本地预查 | SOCKS5 绝不泄漏宿主机真实本地 DNS，彻底防地域穿透 |
| **UDP 协议与 WebRTC** | **原生支持 UDP** | **不支持 UDP（仅限 TCP）** | 网站如开启 WebRTC 检测，HTTP 代理因不支持 UDP 极易暴露本地真实公网 IP |
| **多环境并发加载** | 纯裸 TCP 管道，复用率极高 | 依赖 HTTP Keep-Alive 维持 | 指纹浏览器并发加载数十个图片/JS 资源时，SOCKS5 更稳更流畅 |
| **防关联安全评分** | **高**（干净独立的环境伪装） | 中等 | 各指纹浏览器平台均优先建议配置 SOCKS5 |

> **选型建议**：**强烈推荐优先选择 `SOCKS5` 协议**。若有特定的老旧采集脚本只支持 HTTP 协议，填 `HTTP` 也可无缝直通。

## 快速上手

### 1. 一键启动容器 (开箱即用)

项目采用现代化的 **零配置 (Zero-Config)** 设计，无需手动创建任何 `.env` 明文文件：

```bash
# 一键启动（初次启动将提示终端输入账号密码，密码输入无回显，自动采用硬件指纹 AES-256-GCM 加密）
./aijiasu up

# 也可以随时查看或更新凭据：
./aijiasu auth    # 查看当前机器凭据加密状态
./aijiasu login   # 交互式重新录入并加密凭证
./aijiasu logout  # 安全销毁本地加密凭证
```

### 2. 启动全节点多端口分发服务 (推荐后台运行)

```bash
./aijiasu serve -d
```

输出示例：
```text
[aijiasu OK] 虚拟多端口路由分发服务已成功在后台启动！
• 进程 PID:   75779
• 运行日志:   /Users/wangbaolong/workspace/aijiasu-docker/dispatcher.log
• 查看状态:   aijiasu serve status
• 停止服务:   aijiasu serve stop
• 端口映射表: aijiasu ports
```

## 内置 Web 可视化控制台 (Dashboard)

分发服务启动后，原生内置了轻量级、零依赖的现代 Web 可视化管理控制台：

- **控制台地址**：[http://127.0.0.1:1078](http://127.0.0.1:1078)
- **纯原生内嵌**：无需安装 Node.js、NPM 或任何前端依赖，Go 二进制文件原生内嵌，断网环境亦可秒开。

### 核心功能体验：
1. **首屏双栏工作台布局 (Zero Scroll 首屏即览)**：
   - 彻底优化单屏展示密度：将页面重构为**左侧【节点端口映射工作台】 + 右侧【实时调度日志终端视窗】**左右双栏并列呈现。
   - 打开页面**无需滑动任何鼠标滑轮**，左边查阅节点与分页切换，右边实时滚动展示端口请求、热切换耗时与握手日志，实现“左边看节点，右边看反应”的极致协同。
2. **全量 2810 节点轻量分页 (默认 10 条/页)**：
   - 默认每页展示 10 条（可选 10/15/25/50 条），表格高度严密控制在首屏视野内，不溢出、不突兀。
   - 配备完整的分页控制器（首页、上一页、智能折叠页码、下一页、末页与跳页），可顺畅浏览全量 2810 个节点。
3. **清爽浅蓝科技视觉风格**：
   - 采用现代云原生控制台设计理念，通透浅蓝微渐变背景与微浮白卡片，长时间高频使用清爽护眼。
4. **顶部紧凑状态横条与容灾开关**：
   - 顶部单行集成当前活动节点、出口真实 IP、覆盖端口数、活跃连接数、切换冲突数及运行时长；
   - 顶部直接内嵌【同城容灾策略】小开关，默认黄标【严格锁定模式】，点击即可无感切换。
5. **毫秒级极速检索与一键配置**：
   - 支持按端口、城市、省份或节点名即时搜索，内置精选热门城市快速直达胶囊。
   - 点击“📋 复制”即可将对应端口配置拷入剪贴板，贴入指纹浏览器即可使用。
6. **一键导出指纹浏览器 CSV**：

## 节点云端动态同步与更新 (`./aijiasu sync`)

由于爱加速官方会不定期新增优质节点或下线故障节点，本项目提供了**安全增量同步命令**：

```bash
# 智能安全增量同步 (推荐)
./aijiasu sync
# 或别名:
./aijiasu update
```

### 同步机制与保护原则：
1. **已有端口绝不漂移 (100% 锁定)**：
   - 算法会精准锁定所有已有有效节点的端口，**绝不打乱指纹浏览器中已配置好的环境端口**。
2. **新增节点自动追加**：
   - 官方新增的节点会自动分配在当前最大端口之后（如 `3890`, `3891`...），并自动计算归属省份与城市。
3. **下线节点安全注销**：
   - 官方已注销的节点会自动从活动端口表中清理，避免指纹浏览器误连失效节点。
4. **服务无感热重载**：
   - 同步完成后，若后台分发服务正在运行，系统会自动执行**毫秒级平滑热重载**，使新增节点的端口立刻进入可监听状态。
5. **可选全量重排**：
   - 若需要彻底重新按照全国省份从 `1080` 重新紧凑连续排布，可使用全量重排模式：
     ```bash
     ./aijiasu sync --reorder
     ```

## 高可用与自愈保障机制

为保障指纹浏览器在全天候无人值守、高频采集或长时间挂机业务下的极端稳健性，系统实现了四重高可用加固：

### 1. 同城智能故障转移 (Smart Failover · 默认关闭 · 严格锁定)
* **严格锁定原则 (默认开启)**：为了防止指纹浏览器在不知情的情况下发生物理节点与 IP 漂移（例如用户配置了北京#1，绝不能私自换成北京#2），**系统默认采用【严格锁定模式】**。若专属节点不可用直接报错拦截，坚决不发生任何物理节点漂移，确保指纹环境防关联的绝对安全。
* **按需开启同城容错**：若您的业务属于批量爬虫或低风控采集，希望某个专属节点超时时自动就近接替同城其他备用节点，可**自主开启**：
  ```bash
  # 开启同城容灾转移 (专属节点超时时秒级接替同城备用节点)
  ./aijiasu failover on

  # 恢复严格锁定模式 (默认，绝不漂移物理节点)
  ./aijiasu failover off

  # 查看当前容灾策略
  ./aijiasu failover status
  ```
  *(💡 您也可以在 Web 控制台 [http://127.0.0.1:1078](http://127.0.0.1:1078) 顶部的策略横幅上一键点击开关，即时动态生效)*

### 2. 后台 Watchdog 健康巡检与静默自愈
* **业务痛点**：笔记本电脑合盖休眠唤醒、Wi-Fi 切换或宿主机跨夜网络重置后，底层代理长连接容易变成僵死链路。
* **自愈机制**：分发器内置独立后台 Watchdog 协程，每 45 秒对后端链路进行非阻塞存活握手探测。连续 2 次探测异常时，**自动静默重连原节点并重新打通出口流量**，无需人工干预。

### 3. 长连接感知与平滑冲突保护 (Concurrency Guard)
* **业务痛点**：当环境 A 正在下载大文件，环境 B 突然发起了不同节点的访问。
* **保护机制**：调度器使用原子计数器感知当前正在传输的活跃长连接。一旦触发跨节点切换，调度器在平滑保障旧连接传输的同时完成新环境接替，并在 Web 面板与日志中记录冲突统计，便于评估多任务节奏。

### 4. Linux / macOS 文件句柄自动调优 (`ulimit -n`)
* 启动时自动检测系统 `RLIMIT_NOFILE` 并无感提升至 `65535`，确保 2810 个端口及后续万级并发连接无任何 `too many open files` 异常，并在低配虚拟机上提供明确的终端提权指引。

## 常见问题与 FAQ

### Q1: 爱加速账号并发限制为 1，指纹浏览器多个环境同时打开网页会怎样？
分发调度器内部内置了**并发排队互斥锁**：
- 当环境 A（北京 1080）和环境 B（上海 1227）在同一时刻发起访问时，调度器会串行排队切换节点并维持各自的 TCP 链路，切换仅需 2~3 秒，浏览器会平滑等待页面加载，**绝不会触发官方客户端被踢下线或封号的风险**。

### Q2: 为什么我的指纹浏览器连接某个端口显示“连接失败”？
1. 请确认是否执行了 `./aijiasu serve -d` 启动分发服务（运行 `./aijiasu serve status` 检查状态）；
2. 请确认 Docker 容器处于运行状态（运行 `./aijiasu status` 检查）；
3. 检查端口号是否在 `1080 ~ 3889` 范围内。

### Q3: 本机同时监听 2810 个端口会不会占用过高系统资源？
不会。Go 原生 netpoll 基于 macOS 的 `kqueue` 与 Linux 的 `epoll` 事件驱动机制，单进程激活 2810 个 TCP listener 耗时仅 **67ms**，内存常驻仅约 30MB，CPU 占用低于 0.1%，系统负载极低。
